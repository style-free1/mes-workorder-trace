# MES Demo 设计说明

> 一个面向求职演示的 MES 最小闭环：工单下达 → 开工 → 报工 → 工序卡控 → 序列号追溯 → 完工报表。
> 技术栈：C# / .NET 8 WinForms / SQL Server / ADO.NET。

---

## 1. 项目定位

完整 MES 是几十人年的产品。本项目的目标不是"做一个 MES"，而是用最小范围证明三件事：

1. **理解业务**：工单、工艺路线、工序卡控、序列号追溯在车间里怎么运转。
2. **能写对逻辑**：跳站、漏序、重复过站这些现场高频异常，系统层面怎么拦住。
3. **能交付**：从数据库脚本、代码到可运行的桌面程序，一个人走完。

因此范围刻意收窄为一条主线：**一个工单、一条工艺路线、一个产品序列号的全生命周期**。质量、Andon、WMS 只留数据模型上的扩展位，不实现。

---

## 2. 业务主线

### 2.1 核心理念

MES 的核心不是"记录生产"，而是**用系统规则约束现场作业**。车间最常见的三类问题是：

- **跳站/漏序**：上一道工序没做，直接扫下一道。GP12 漏检、漏旋铆都属于这一类。
- **重复过站**：同一个产品同一道工序被扫两次，产量虚高。
- **状态错乱**：工单没下达就开工、产品没完工就入库。

本项目的卡控逻辑就是围绕这三类问题设计的。

### 2.2 工单状态机

```
Created ──下达──> Released ──开工──> InProgress ──全部完工──> Completed
   │                  │                    │
   └── 可编辑          └── 可创建 SN        └── 可报工
```

| 状态 | 含义 | 允许操作 |
|---|---|---|
| Created | 已创建，未下达 | 编辑、删除、下达 |
| Released | 已下达，可生产 | 开工、创建 SN |
| InProgress | 生产中 | 报工、创建 SN |
| Completed | 全部产品完工 | 查看、追溯 |
| Closed | 已关闭 | 只读 |

### 2.3 产品序列号（SN）流转

每个产品从创建起分配唯一 SN，按工艺路线逐序过站：

```
SN 创建 ──> 机加(10) ──> 旋铆(20) ──> 总装(30) ──> 压装(40) ──> GP12(50) ──> 完工
              │            │            │            │            │
              └─ 每站写 PassRecord，记录工位、操作人、结果、时间
```

- `ProductSN.CurrentStepSeq` 记录当前已完成的最后一道工序序号。
- 每次报工，系统计算"下一道应过工序"，与扫描的工序比对，不一致直接拒绝。
- 最后一道工序完成后，SN 状态置为 `Completed`；当工单下所有 SN 完工，工单自动 `Completed`。

## 3. 卡控规则（面试重点）

| 编号 | 规则 | 触发场景 | 系统行为 |
|---|---|---|---|
| R1 | 工单必须已下达 | 工单为 Created 时创建 SN/报工 | 拒绝，提示"工单未下达" |
| R2 | SN 必须存在且属于该工单 | 扫描了别的工单或不存在的一维码 | 拒绝，提示"SN 不存在或不属于当前工单" |
| R3 | 不能跳站 | 当前应过 20，扫描 30 | 拒绝，提示"当前应过工序：旋铆(20)，不能跳站" |
| R4 | 不能重复过站 | 已过 20，再次扫描 20 | 拒绝，提示"该产品已完成此工序" |
| R5 | 上一道必须完成 | 上道工序状态非 Completed | 拒绝，提示"上一道工序未完成" |
| R6 | 不良品不推进 | 报工结果为 NG | 记录 NG 记录，SN 不推进，提示"已记录不良，请走返修" |
| R7 | 工单数量上限 | 创建 SN 超过计划数量 | 拒绝，提示"已达工单计划数量" |

> 这七条规则对应真实车间的七类异常。面试时能逐条讲出"为什么需要它、不拦会怎样"，比背 MES 模块列表有说服力。

## 4. 数据模型

### 4.1 表清单

| 表 | 作用 | 关键字段 |
|---|---|---|
| Material | 物料主数据 | MaterialCode, MaterialName |
| Operation | 工序字典 | OperationCode, OperationName, SeqNo |
| Routing | 工艺路线头 | RoutingCode, MaterialId |
| RoutingStep | 工艺路线工序 | RoutingId, OperationId, StepSeq, IsKeyStep |
| Workstation | 工位 | WorkstationCode, OperationId |
| WorkOrder | 工单 | WorkOrderNo, MaterialId, RoutingId, PlanQty, Status |
| WorkOrderStep | 工单工序任务 | WorkOrderId, StepSeq, PlanQty, DoneQty, Status |
| ProductSN | 产品序列号 | SN, WorkOrderId, CurrentStepSeq, Status |
| PassRecord | 过站记录 | SN, OperationId, StepSeq, WorkstationCode, Result, PassedAt |
| SysUser | 用户与角色 | UserName, DisplayName, Role |

### 4.2 关系

```
Material 1──N Routing 1──N RoutingStep N──1 Operation
   │                              │
   └────────── 1──N WorkOrder 1──N WorkOrderStep
                        │
                        └── 1──N ProductSN 1──N PassRecord
```

### 4.3 设计取舍

- **工艺路线与工单工序分离**：路线是模板，工单工序是快照。路线后续变更不影响已下达工单，这是 MES 的常见做法。
- **PassRecord 存 SN 字符串而非外键**：过站记录是流水数据，允许在 SN 归档后仍可查询；用索引保证查询性能。
- **不做软删除**：演示项目保持简单，生产环境应加 IsDeleted/审计字段。

## 6. 技术选型

| 选择 | 理由 |
|---|---|
| C# WinForms | 国内 MES 客户端主流；现场工控机多为 Windows + 桌面程序 |
| SQL Server | MES 项目最常用的关系库；与目标岗位技术栈一致 |
| ADO.NET 手写 SQL | 展示 SQL 能力与事务控制；不依赖 ORM，面试可讲清每条语句 |
| 三层结构（Forms / Services / Data） | 界面与业务分离，卡控逻辑集中在 Service，便于测试与讲解 |

### 关键实现点

- **报工使用事务**：写 PassRecord、更新 ProductSN、更新 WorkOrderStep 三张表在同一事务内，任一步失败回滚。
- **卡控逻辑集中在 `MesService.PassStation`**：界面只负责收集参数和展示结果，业务规则不散落在按钮事件里。
- **连接字符串可配置**：默认 `Server=.\SQLEXPRESS;Database=MesDemo;Trusted_Connection=True;TrustServerCertificate=True;`，换机器只改一处。

## 7. 三分钟讲解脚本

> 面试官：介绍一下你这个项目。
>
> 我：这是一个 MES 最小闭环，核心解决车间三类异常：跳站、重复过站、状态错乱。
>
> 主线是一个工单下达后，每个产品分配唯一 SN，按工艺路线逐序过站。每次报工，系统会算当前产品下一道应过工序，和扫描的工序比对——不一致就拒绝，比如当前该做旋铆，扫了总装，系统会提示"不能跳站"。这条规则对应我在拓普遇到的 GP12 漏序问题：现场网络波动或扫 A 做 B，会导致检测工序没有记录，但如果系统按工艺路线强制卡控，漏序在下一站就会被拦住。
>
> 数据上是三张核心表：工单工序任务、产品 SN、过站记录。报工时三张表在同一事务里更新，保证不会出现"记录写了但状态没推进"。
>
> 追溯支持两个方向：输入 SN 看它经过的每道工序、工位、操作人、时间；输入工单看所有 SN 的完成状态。

## 8. 后续扩展

| 质量 | 增加 Inspection/Defect 表，GP12 工序挂检验项 |
